# Autonomous Re-Sequencing — Fractal Pivot Chain (Criterion 1 evidence)

> **This demonstrates autonomous re-sequencing:** the agent's findings seed its next
> investigative steps. When a pivot finding warrants going deeper, its `follow_ups`
> re-enter the spawn queue as a **new, deeper pivot** (`depth = parent.depth + 1`,
> `parent_id = parent.spawn_id`), bounded at `max_depth = 3` / `max_width = 16`. So the
> investigation **plan adapts to what the agent finds** — it is not a fixed script.
>
> These ephemeral **fractal pivot agents** are distinct from the **60 persistent
> sensor micro-agents** (edr / suricata / yara / zeek / volatility …): the sensors run
> continuously and are never "spawned"; the pivot agents are short-lived, spawned on
> demand from a finding, and dissolve after reporting.

## Honest disclosure (what is real vs scaffolded)

- **Real:** the `Watcher` recursion, the lineage (`parent_id`/`seed_technique`/
  `depth`), and the SLM `pivot_infer` at every node (each a ~20–40 s CPU inference).
  The **decision to emit `follow_ups` and re-sequence deeper is the model's own.**
- **Scaffolded for this artifact:** because the pivot SLM runs on CPU (~30 s/pivot)
  and the production TTL is 2 s, this one-time generation widened the TTL and took a
  single follow-up per level (`max_width=1`) to yield a clean linear depth-0→2 path.
  The signed-ledger write requires the `findevil` service account's Ed25519 key (the
  running `findevil watcher` daemon does this in production); this capture proves the
  lineage without that key. Nothing in the chain is hand-authored.
